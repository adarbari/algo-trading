## The idea in four sentences

An **edge** is a typed document: a thesis, the reason it persists (capacity, mandate, horizon,
work, a risk nobody wants), an **outcome** (horizon, benchmark, path), an evaluation schedule, a
universe, and the **screeners** that implement it. A screener stays what it is today (a rule screen
or a Python `Screener`); one edge lists several, and the **harness** scores each one point in time
against stored outcomes: hit rate against the base rate, lift, decile spread, by year and regime,
with a frozen period and a trial log. The trader sees the evidence as an odds line on Ideas, a
track-record chip on the Screeners list and a plain Edges list. ML is an offline discovery tool
and one more screener implementation, never the judge.

Why: "if it worked someone would have used it" is answered per edge by a written persistence
reason, not by a model. The store's bars start 2024-10-03, so only short-horizon edges (10 to 60
sessions) have complete labels today; the harness is proven on those before any decade-long
backfill.

## Measures (the harness's definitions; tested in `tests/unit/services/evaluation/`)

For each session S in the edge's schedule: run the screener for S on what was known at S; take
the top K (from the edge document, or all qualified). For each pick, hit = 1 if the edge's
outcome condition held for (instrument, S), else 0; a window not yet closed is excluded, never a
miss. Hit rate at S = hits / picks. Base rate at S = hits / all eligible names at S under the same
condition. Lift = hit rate / base rate. Magnitude: the mean excess return of the picks, and the
decile spread (every eligible name ranked by score; top-decile mean forward return minus bottom).
Reported per year, per regime label (`regime@v3`) and for the frozen period on its own, with the
number of independent sessions beside every number. Evaluation sessions are spaced at least one
horizon apart. Every variant tried is a row in the run's trial log.

## The quality bar (an edge document is accepted only when it answers all nine)

1. Mechanism: who is forced, constrained or systematically wrong, and why they do not fix it.
2. Persistence: why it survives being known.
3. Outcome: horizon, benchmark, path (drawdown cap), matching how the trade would be held.
4. Trigger timing: the moment the trigger is known (`known_from`) and the first session we act.
5. Faithful replication first: the source's own rule as screener v1 and the published number.
6. Expected size and sample: published magnitude, what remains after decay, at least 40
   independent events in the history held, else the edge waits.
7. Capacity and costs: typical volume, cost per trade, whether an individual can enter and exit.
8. Failure modes and the retirement rule.
9. Decoys: the simpler explanation (size, momentum, illiquidity); the harness compares against
   the size and momentum baselines on the same sessions.

Rejected and blocked candidates are kept with the reason so the same idea is not re-filed.
Checked 2026-10-07: S&P 500 index changes rejected (Greenwood and Sammon: under 1% since 2010);
leveraged ETF rebalancing rejected (intraday, weak after costs); Russell reconstitution blocked
(alive, about 1% over 20 sessions, one event a year, no membership data).
